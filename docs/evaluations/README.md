# RAG 本地评测记录

新增：[真实历史 DeepSeek 评测报告](rag-real-2026-09-11.md)与[质量评测流程](../rag-evaluation.md)。真实语料及逐题回答仅保存在 Git 忽略目录；下文为早期合成集结果，不能与新报告直接比较模型优劣。

`rag-2026-09-11.json` 是最终实现的一次真实 Ollama 运行，包含运行环境、核心模块代码哈希、逐题结果与生成原文。`rag-baseline-2026-09-11.json` 保留早期 1.7B 模型、未收紧上下文时的失败结果；两次运行同时改变多个因素，不能把差异单独归因于模型大小。

数据为手工编写的 10 个合成会话、40 个可回答问题与 10 个无答案问题。是开发回归集，**不是生产准确率或独立留出集**。

| 方式 | Recall@5（会话） | MRR@5 | 子块方案文本覆盖 | 扩展上下文方案文本覆盖 | 检索 P95 |
| --- | --- | --- | --- | --- | --- |
| 关键词 | 39/40 | 0.9208 | 27.5% | 97.5% | 3.2 ms |
| 向量 | 40/40 | 0.9750 | 32.5% | 100% | 2.80 s |
| 混合 | 40/40 | 0.9750 | 35% | 97.5% | 2.80 s |

Windows Node v22.14.0 使用 `bm25-scan` 后端。向量为 `qwen3-embedding:0.6b`，生成模型为 `qwen3:4b`。默认每次模型请求后卸载，延迟包含模型加载。8 个可回答抽样问题实际调用生成模型，4 个无答案问题通过证据门槛直接拒答，不能称为模型拒答率。生成阶段 P95 为 6.97 秒。没有调用错误或结构错误。

人工阅读发现至少两个需要继续改进的例子：

- `index-1`：将早期未解决状态与后期测试通过混在一起，缺少清晰的时间区分。
- `vector-1`：包含与问题不直接相关的其他会话结论。

所以本轮证明的是链路可运行、上下文扩展能增加方案文本覆盖；没有证明所有生成结论都准确。引用存在校验不是语义蕴含校验。后续应建立真实历史的独立人工标注集，测量引用支持率、失败方案误判率及无答案场景，再决定是否引入重排和结果状态抽取。

回归检查：新增 15 项 RAG 核心/HTTP/UI 检查在 Node 和 Electron 运行时通过。完整项目测试运行曾在既有文件监听短时序用例失败，单独复测通过；后续 RAG、静态站点和配置检查已补跑。Bash 部署测试因当前 Windows 主机缺少 Bash 跳过。
